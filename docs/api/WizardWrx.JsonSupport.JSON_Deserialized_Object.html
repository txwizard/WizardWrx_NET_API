Class JSON_Deserialized_Object

Instances of this class provide a lightweight, schema-aware façade over a JSON payload. The class optionally sanitizes the input, validates required fields, and exposes a minimal set of typed accessors so callers can retrieve field values without depending directly on JSON.NET, working with JToken instances, or needing to expend the effort to parse the JSON into a strongly-typed model when only a few fields are needed.

Remarks

The typed getters intentionally cover only the canonical .NET types that map cleanly and unambiguously to JSON: string, Boolean, 32-bit integer, double-precision floating point, Guid, and DateTime. JSON does not define numeric widths, temporal subtypes, or alternative Boolean representations, so additional getters (such as byte, short, long, float, DateOnly, DateTimeOffset, or truthy/falsy coercions) would not provide meaningful additional capability. Callers who require more specialized interpretations can retrieve the raw string value and apply domain-specific parsing rules.

This design keeps the API surface minimal, deterministic, and intention-revealing, while insulating callers from JSON.NET and preserving the ability to evolve the internal representation in the future.

Examples

The following example shows a typical usage pattern for this class: 

// Raw JSON received from an external source.
string json = @"
{
    "id": "c0a8012e-5f3c-4b8f-9b7a-2f4f0e9c1a12",
    "name": "Alice",
    "age": 42,
    "active": true,
    "created": "2024-10-12T14:30:00Z"
}";

// Define the fields that must be present.
var required = new[] { "id", "name", "active" };

// Create the wrapper.
var wrapper = new JsonFieldAccessor(json, required);

// Validate the payload.
var missing = wrapper.Validate(requireNonEmptyValues: true);
if (missing.Count > 0)
{
    Console.WriteLine("Missing or invalid fields:");
    foreach (var field in missing)
        Console.WriteLine("  " + field);
    return;
}

// Retrieve typed values.
Guid? id = wrapper.GetFieldValueAsGuid("id");
string name = wrapper.GetFieldValueAsString("name");
int? age = wrapper.GetFieldValueAsInt("age");
bool? active = wrapper.GetFieldValueAsBoolean("active");
DateTime? created = wrapper.GetFieldValueAsDateTime("created");

Console.WriteLine($"User {name} ({id})");
Console.WriteLine($"Age: {age}");
Console.WriteLine($"Active: {active}");
Console.WriteLine($"Created: {created:u}");

This example demonstrates validation, typed field retrieval, and the absence of any dependency on JSON.NET in the calling code.

The following example demonstrates how to handle optional fields: 

string json = @"
{
    "username": "bob",
    "email": "bob@example.com",
    "age": "not-a-number",
    "lastLogin": null
}";

var required = new[] { "username" };
var wrapper = new JsonFieldAccessor(json, required);

// Validate required fields only.
var missing = wrapper.Validate(requireNonEmptyValues: true);
if (missing.Count > 0)
    throw new InvalidOperationException("Required fields missing.");

// Optional fields: callers decide how to interpret nulls.
string email = wrapper.GetFieldValueAsString("email");   // "bob@example.com"
int? age = wrapper.GetFieldValueAsInt("age");            // null (invalid integer)
DateTime? lastLogin = wrapper.GetFieldValueAsDateTime("lastLogin"); // null

Console.WriteLine($"User: {email}, Age: {age}, Last Login: {lastLogin}");

This example shows how optional fields naturally map to nullable return values, allowing callers to apply their own fallback or defaulting logic.

The following example shows how callers can apply domain-specific parsing rules when the built-in typed accessors intentionally avoid coercions: 

string json = @"
{
    "enabled": "yes",
    "expires": "2024-10-12T14:30:00-05:00",
    "priority": "high"
}";

var wrapper = new JsonFieldAccessor(json, Array.Empty<string>());

// Built-in Boolean accessor returns null because "yes" is not a JSON Boolean.
bool? enabled = wrapper.GetFieldValueAsBoolean("enabled");   // null

// Domain-specific truthy/falsy parsing.
string rawEnabled = wrapper.GetFieldValueAsString("enabled");
bool enabledFlag = rawEnabled?.Equals("yes", StringComparison.OrdinalIgnoreCase) == true;

// Built-in DateTime accessor parses the timestamp but normalizes the offset.
DateTime? expires = wrapper.GetFieldValueAsDateTime("expires");

// Domain-specific offset-preserving parsing.
string rawExpires = wrapper.GetFieldValueAsString("expires");
DateTimeOffset dto = DateTimeOffset.Parse(rawExpires);

Console.WriteLine($"Enabled: {enabledFlag}");
Console.WriteLine($"Expires (DateTime): {expires}");
Console.WriteLine($"Expires (DateTimeOffset): {dto}");

This example illustrates how callers can retrieve the raw string when they need to apply custom Boolean rules, preserve timezone offsets, or interpret values according to domain-specific semantics.

The return value is a nullable Boolean representing the value of the field, or null if the field does not exist or cannot be parsed as a Boolean.
Remarks

JSON has a native Boolean type, and JSON.NET preserves it directly, so this accessor returns true or false only when the underlying token is a JSON Boolean or a string that .NET recognizes as a Boolean literal (“true” or “false”, case-insensitive). JSON.NET does not coerce other string values to Boolean, and the .NET framework does not define truthy/falsy semantics for values such as “yes”, “no”, “0”, or “1”. Callers who require more flexible Boolean interpretation should retrieve the raw string and apply domain-specific rules.

Remarks

This method provides the canonical double precision floating point number accessor for this class.

This method retrieves the field value as a DateTime. Since JSON has no native date or time type, and date values are represented as strings. This method parses those strings using System.DateTime.TryParse(System.String,System.DateTime@), which is sufficient for ingestion scenarios where the exact original offset is not required and the primary goal is to obtain a usable DateTime value.

A DateTimeOffset getter is intentionally omitted because JSON does not guarantee the presence or meaning of timezone offsets, and callers who require offset-preserving semantics can parse the raw string explicitly using System.DateTimeOffset.Parse(System.String).
